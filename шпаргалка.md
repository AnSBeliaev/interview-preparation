# Шпаргалка

## DDL

```sql
price numeric(12, 2) NOT NULL CHECK (price >= 0)
created_at timestamptz NOT NULL DEFAULT now()
id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY
customer_id bigint NOT NULL REFERENCES customers (id) ON DELETE RESTRICT
order_id bigint NOT NULL REFERENCES orders (id) ON DELETE CASCADE
product_id integer REFERENCES products (id) ON DELETE SET NULL
```

`smallint` / `integer` / `bigint` — целые, разный диапазон. Деньги — `numeric`, не `real`. `varchar(n)` ограничен, `text` нет, в Postgres по скорости они равны. `char(n)` дополняет пробелами. `timestamp` без пояса, `timestamptz` — момент. `serial` — старая короткая запись последовательности. В новой схеме — `GENERATED ALWAYS AS IDENTITY`. `json` хранит текст, `jsonb` разбирают и индексируют.

`ALTER TABLE t ADD COLUMN ...` / `DROP COLUMN` / `ALTER COLUMN ... TYPE ...` / `ADD CONSTRAINT ... CHECK (...)`.

## Запросы и индексы

`WHERE` до группы, `HAVING` после. `JOIN` оставляет пары. `LEFT JOIN` сохраняет левую сторону. `count(fk_id)` после левого соединения не считает строку без пары.

B-tree по умолчанию: `=`, диапазон, `BETWEEN`, `IN`, `ORDER BY`, `LIKE 'abc%'`. Не ведущий `%`, не почти все строки, не функция поверх колонки. GIN на JSONB: `CREATE INDEX ... USING gin (attrs)` и `attrs @> '{"color":"red"}'`.

## Git

Заголовок до 50 символов, пустая строка, тело. `feat` / `fix` / `perf` / `refactor`.

Конфликт: верх `HEAD`, низ входящая ветка, маркеры удалить, `git add`, `git commit`.

Свою непушеную ветку — rebase. Общую историю — merge. `cherry-pick` переносит один коммит и даёт новый хеш.

`revert` — новый отменяющий коммит. `reset --soft` снимает коммит, правки в индексе. `--mixed` — правки в файлах. `--hard` выбрасывает их. После `--hard` коммит ищут в `git reflog`.

## JSON и REST

Шесть типов: string, number, boolean, array, object, null. Даты нет, ISO 8601 строкой. Байтов нет, Base64. XSD — схема XML. XML, когда схему дала другая сторона. Свой API — JSON.

`GET` не меняет данные. `POST` не идемпотентен. `PUT` заменяет целиком. `PATCH` меняет часть. `DELETE` повторно безопасен. `2xx` успех, `4xx` запрос, `5xx` сервер. `201` создали. `401` кто вы. `403` нельзя. `409` конфликт состояния.

## DWH

OLTP — операция сейчас, Postgres, строка целиком. OLAP — агрегаты по истории. ETL меняет до загрузки. ELT грузит сырьё и меняет SQL внутри. Факт — события и числа (`order_items`). Измерение — справочник (`customers`, `products`). Витрина — готовый срез под отчёт. ClickHouse хранит колонки отдельно, поэтому одна сумма читает одну колонку.
