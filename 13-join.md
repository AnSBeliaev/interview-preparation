# JOIN

Текст для человека, который бэкенд раньше не писал. Примеры на магазине: клиенты и заказы. Таблицы при `JOIN` не меняются. Новая таблица на диске не появляется. На экране только ответ этого запроса.

## Зачем он нужен

Почта лежит в `customers`. Сумма заказа лежит в `orders`. В заказе нет почты, там записан только номер клиента.

Клиенты:

| id | email |
| --- | --- |
| 1 | anna@example.com |
| 2 | boris@example.com |
| 3 | no-orders@example.com |

Заказы:

| id | customer_id | status | total_amount |
| --- | --- | --- | --- |
| 1 | 1 | paid | 2340.50 |
| 2 | 1 | new | 120.00 |
| 3 | 2 | cancelled | 350.00 |

Чтобы в одной строке ответа увидеть и почту, и сумму, две строки ставят рядом. Это и делает `JOIN`.

## Что получается в ответе

Одна пара — одна широкая строка. Сначала колонки заказа, справа колонки клиента. Под ней следующая пара, тоже в одну строку.

Заказ 1 и Анна по отдельности:

| id | customer_id | status | total_amount |
| --- | --- | --- | --- |
| 1 | 1 | paid | 2340.50 |

| id | email |
| --- | --- |
| 1 | anna@example.com |

После склейки это одна строка:

| id | status | total_amount | email |
| --- | --- | --- | --- |
| 1 | paid | 2340.50 | anna@example.com |

У Анны два заказа, поэтому в ответе две строки с её почтой. Борис даёт одну строку. Клиент без заказов пару не даёт.

## Команда по словам

```sql
SELECT o.id, o.status, o.total_amount, c.email
FROM orders AS o
JOIN customers AS c ON c.id = o.customer_id;
```

- `FROM orders AS o` — левая таблица, заказы. Буква `o` — короткое имя `orders` внутри этого запроса. Его выбрали сами, на месте `o` может быть любое слово.
- `JOIN customers AS c` — правая таблица, клиенты. Буква `c` значит `customers`.
- `ON` — ключевое слово. Оно открывает правило склейки. Само по себе ничего не сравнивает.
- `c.id = o.customer_id` — правило. Номер клиента равен номеру, записанному в заказе. Знак `=` здесь оператор, как в `WHERE`.
- `SELECT` перечисляет, какие колонки из склеенной строки показать. Точка значит «колонка этой таблицы»: `o.id` — номер заказа, `c.email` — почта клиента.

База идёт по заказам.

1. Заказ 1, `customer_id` равен 1. Клиент 1 — Анна. В ответ строка: заказ 1, `paid`, `2340.50`, `anna@example.com`.
2. Заказ 2, тоже клиент 1. Снова Анна. Вторая строка ответа.
3. Заказ 3, клиент 2. Борис. Третья строка.
4. Клиент 3 ни в одном заказе не записан. Обычный `JOIN` его не берёт.

Ответ:

| id | status | total_amount | email |
| --- | --- | --- | --- |
| 1 | paid | 2340.50 | anna@example.com |
| 2 | new | 120.00 | anna@example.com |
| 3 | cancelled | 350.00 | boris@example.com |

`JOIN` и `INNER JOIN` — два написания одного и того же. В ответе только пары.

Начать можно и с клиентов: `FROM customers AS c JOIN orders AS o ON ...`. Для обычного `JOIN` набор строк тот же. Меняется только то, какая таблица написана первой.

## Одинаковое имя колонки

Колонка `id` есть и у заказа, и у клиента. Запрос `SELECT id` упадёт: база не знает, чей это номер. Пишут, из какой таблицы брать.

```sql
SELECT o.id AS order_id, c.id AS customer_id, c.email
FROM orders AS o
JOIN customers AS c ON c.id = o.customer_id;
```

`o.id` — номер заказа. `c.id` — номер клиента. Слово после `AS` — имя колонки только в ответе. В таблицах имена остаются `id`.

У заказа 3 эти числа разные: заказ номер 3, клиент номер 2. У заказа 1 они совпали случайно: и заказ, и Анна имеют номер 1. Это разные колонки.

Почта есть только у клиентов, поэтому `email` можно писать без `c.`. С `c.email` тоже правильно, так сразу видно, откуда колонка.

## LEFT JOIN

`LEFT JOIN` клеит так же. Разница одна: строка левой таблицы остаётся в ответе, даже если пару справа не нашли. Колонки правой таблицы в этой строке пустые. Пустота называется `NULL`. Это не ноль и не пустой текст. Значения нет.

Левая таблица — та, что в `FROM`, до слова `JOIN`. В запросе ниже слева клиенты. Их нельзя потерять.

```sql
SELECT c.email, o.id AS order_id, o.status
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
ORDER BY c.email, o.id;
```

1. Анна, номер 1. К ней клеятся заказы 1 и 2. Две строки.
2. Борис, номер 2. К нему клеится заказ 3. Одна строка.
3. `no-orders@example.com`, номер 3. Заказа с `customer_id` 3 нет. Клиент в ответе остаётся. `order_id` и `status` пустые.

| email | order_id | status |
| --- | --- | --- |
| anna@example.com | 1 | paid |
| anna@example.com | 2 | new |
| boris@example.com | 3 | cancelled |
| no-orders@example.com | NULL | NULL |

Обычный `JOIN` с тем же `ON` напечатал бы только первые три строки.

Клиенты, у которых заказов нет:

```sql
SELECT c.email
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE o.id IS NULL;
```

`WHERE o.id IS NULL` стоит после склейки. Остаются только те левые строки, которым справа ничего не приклеилось. Здесь это `no-orders@example.com`.

Фраза: «Пара обязана быть — `JOIN`. Нужна и сторона без пары — `LEFT JOIN`. Слева пишу ту таблицу, которую нельзя потерять».

## Остальные виды

Их достаточно назвать. Писать на собесе просят `JOIN` и `LEFT JOIN`.

`RIGHT JOIN` оставляет все строки правой таблицы, той, что после слова `JOIN`. Пары слева нет — левые колонки пустые. То же самое почти всегда пишут как `LEFT JOIN`, поменяв таблицы местами. Запрос «все заказы, даже если клиента нет» можно начать с заказов и написать `LEFT JOIN`. Правый вид из-за этого почти не используют.

`FULL JOIN` оставляет обе стороны. Нет клиента для заказа — пустые колонки клиента. Нет заказа у клиента — пустые колонки заказа. В нашем магазине заказа без клиента не бывает: колонка `customer_id` обязательна. Поэтому `FULL JOIN` здесь совпадёт с `LEFT JOIN` от клиентов.

`CROSS JOIN` клеит каждую строку левой таблицы с каждой строкой правой. Правила `ON` нет. 3 клиента и 3 заказа дают 9 строк. Среди них будут и бессмысленные пары: Анна рядом с заказом Бориса. На собесе это называют декартовым произведением. В магазине его не используют: пары должны сходиться по номеру.

## Что сказать, если попросят своими словами

`JOIN` ставит строку заказа рядом со строкой клиента, когда номер в заказе равен номеру клиента. В ответе одна строка на каждую такую пару. У Анны два заказа, поэтому её почта в ответе два раза. Клиент без заказа в обычный `JOIN` не попадает.

`LEFT JOIN` этого клиента сохраняет. Колонки заказа у него пустые, `NULL`. Левая таблица — та, что написана в `FROM`.

`RIGHT` сохраняет правую, `FULL` обе. `CROSS` соединяет всех со всеми и `ON` не использует.
